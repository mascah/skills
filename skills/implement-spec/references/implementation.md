# Delivering selected scope

Read the selected request or canonical spec/slice, constraints and acceptance.
Local work can use the current checkout with uncommitted inputs identified.
Revalidate Delivery observations against code; plan only the necessary sequence.
Resolve consequential ambiguity before affected work, updating intent in its owner
when scope changes. Small direct tasks need no spec, tickets, setup or plan.

Verify prerequisites through available integrated work and evidence before
performing dependent changes. An abandoned prerequisite, closed issue, worker exit
or unmerged branch alone does not deliver acceptance. Name specific missing inputs
and continue independent authorized work. Preserve partial results.

On resume inspect git, previous evidence and caller-owned running work before
repeating actions. For sustained work retain concise completed slices, outstanding
owners, checks, unresolved findings and the next action in Delivery or a useful
handoff note; do not mirror tracker status or invent a run schema.

Finish with selected/remaining scope, branch/commit or dirty paths, actual checks,
findings, integration state and how to merge or resume. A blocked return gives a
concrete waiting condition. Target merge, publication, external closure and caller
workspace cleanup follow existing authority, never a guessed completion policy.
