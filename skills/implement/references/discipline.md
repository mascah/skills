# Common discipline

Read project instructions and existing workflow preferences. Adopt existing paths,
terminology and decisions; infer missing conventions when sufficient. Plain Markdown
suffices for workflow documents: no required IDs, frontmatter or scaffold. Create only
useful files, preserving other sessions' edits and unrelated user instructions.
For writes, inspect branch/dirty state, existing worktrees and relevant project
check commands. Obey the project's isolation and commit rules. Stage only owned changes; tracker references must be real and are optional.

Stay within the caller's mandate. Discussion, research, drafting and review do not
silently authorize implementation or external publication. Adequate implementation
scope authorizes routine technical choices. Ask about consequential missing intent
or a changed mandate, not repeated permission for authorized decisions. External
writes require user instruction or explicit caller policy; prepare reviewable drafts
first when publication authority is absent. After a partial external-write failure,
inspect actual state before retrying so successful writes are not duplicated.

Before claims, inspect actual evidence. Report checks performed, failures,
unresolved inputs and unexercised integrations. A stub or document review is not
live runtime validation. Never invent unavailable scope or successful execution.
