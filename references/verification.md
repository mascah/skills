# Proportionate verification

Choose checks from observable acceptance and project conventions. Behavioral
changes need meaningful regression/acceptance tests through useful interfaces;
a claimed test-first cycle requires an observed behavioral failure followed by
a pass. Documentation/configuration use document, diff and structural checks.

Inspect command output and the actual diff against requirements and conventions.
For affected interactions, exercise failure, recovery and integration transitions;
component success alone does not prove the connected experience. Fix material
findings within mandate and rerun checks invalidated by changes.

Attach evidence to the tested revision or identified dirty state. Distinguish
implementation, integration on the chosen branch, and merge into the target.
List pending human judgments and unavailable checks. Scope review claims to
what was inspected; an empty diff or successful process exit proves no acceptance.
